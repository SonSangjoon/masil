# MASIL documentation

MASIL's public story begins in the [repository README](../README.md). The documents in this folder
separate product meaning, interaction design, technical behavior, evidence, evaluation, and future
direction so that each claim has one clear owner.

| Question | Document |

## Authority

- Product narrative and the current-versus-future boundary follow the final Devpost story.
- Implementation claims follow inspected code and fresh runtime evidence.
- Performance claims follow frozen evaluation artifacts from the same configuration.
- Human-need and cultural claims follow [Evidence and Korean context](EVIDENCE.md).

The current product is calligraphy and Janggi as two proofs of one accessibility model. Welfare
intake, institutional routing, monitoring, and care coordination are not current MASIL features and
appear only as conditional hypotheses in [Long-term vision](VISION.md).
